# 09 · 部署选型决策表

> 不同场景下，到底该选哪种部署方案？
> 本表帮你 30 秒做出决策

---

## 1. 核心决策：先看你的硬件

```
                    ┌─ 有 NVIDIA GPU 吗？
                    │
         ┌──────────┴──────────┐
         │ 是                    │ 否
         ▼                      ▼
    显存多大？              纯 CPU 部署
         │              ┌───────────┐
   ┌─────┼─────┐        │ Ollama    │（首选，自动优化CPU）
   │     │     │        │ llama.cpp │（手动控制）
   ▼     ▼     ▼        └───────────┘
 ≥16GB  4-8GB  <4GB
   │     │     │
   ▼     ▼     ▼
 任意   量化    小模型
 方案   跑7B    或Ollama
```

## 2. 按使用场景决策

### 2.1 个人学习 / 快速体验
| 场景 | 推荐 | 理由 |
|------|------|------|
| 本地对话 | **Ollama** | 一行命令，5分钟出结果 |
| 学原理 | **Transformers** | 理解加载/量化/推理细节 |
| 无 GPU | **Ollama** | 自动 CPU 优化，体验最好 |
| 测试工具调用 | **Ollama + Qwen2.5** | 原生支持 function calling |

### 2.2 个人项目 / 自用工具
| 场景 | 推荐 | 理由 |
|------|------|------|
| 自用聊天机器人 | **Ollama** | 够用、省心 |
| Agent 开发调试 | **Ollama + OpenAI接口** | base_url 一行切换本地/云端 |
| 知识库问答 (RAG) | **Ollama(生成) + bge(嵌入)** | 全套本地化 |
| 需要固定输出格式 | **Ollama + tools** | 支持结构化输出 |

### 2.3 生产 / 团队使用
| 场景 | 推荐 | 理由 |
|------|------|------|
| 多用户并发 | **vLLM** | 高吞吐，不 OOM |
| 上线服务 | **vLLM + Docker** | 标准服务化 |
| 私有化部署 | **vLLM + FastAPI封装** | 可加认证/RAG/监控 |
| 多模型路由 | **FastAPI 代理层** | 统一入口，动态切换 |
| 内网服务器 | **Docker + vLLM/Ollama** | 一次打包到处跑 |

## 3. 按模型规模决策

| 模型规模 | 显存需求 | 推荐方案 |
|---------|---------|---------|
| 0.5B-1.5B | <4GB | Ollama / llama.cpp / Transformers(CPU也可) |
| 3B | 2-4GB(量化) | Ollama（首选） |
| 7B | 4-8GB(量化) | Ollama / vLLM |
| 13B | 8-16GB(量化) | vLLM |
| 32B | 16-24GB(量化) | vLLM + 量化 |
| 70B | 40GB+ | vLLM + 多卡 |
| 100B+ | 多机多卡 | vLLM + Ray |

## 4. 按部署形态决策

### 4.1 嵌入式（库模式）
```python
# 模型作为 Python 库直接用
from transformers import AutoModelForCausalLM      # 研究/微调场景
from llama_cpp import Llama                         # 轻量推理场景
from sentence_transformers import SentenceTransformer  # 嵌入场景
```

### 4.2 本地服务（进程模式）
```bash
# 模型作为独立服务，应用通过 HTTP 调用
ollama serve                    # 零配置
vllm serve Qwen/Qwen2.5-7B      # 高吞吐
llama-server -m model.gguf      # 底层控制
```

### 4.3 容器化（Docker）
```bash
# 环境一致、易迁移
docker run ollama/ollama
docker build -t my-llm .        # 自定义封装
```

## 5. 按开发阶段决策

```
开发阶段 → 用什么？

┌─────────────────────────────────────────────────────┐
│  1. 想法验证（5分钟）                                │
│     → Ollama（最简单）                              │
│  2. 功能开发（写代码）                               │
│     → Ollama + OpenAI兼容接口（代码与云端一致）      │
│  3. 调优（速度/质量）                                │
│     → Transformers（精细控制参数/量化）              │
│  4. 上线（多用户）                                   │
│     → vLLM + Docker + 负载均衡                      │
│  5. 迭代（加功能）                                   │
│     → FastAPI 代理层（加 RAG/缓存/监控/多模型）      │
└─────────────────────────────────────────────────────┘
```

## 6. 终极决策速查表

| 你的需求 | 一句话答案 |
|---------|-----------|
| 就想在电脑上跑个模型聊天 | **Ollama** |
| 想理解模型怎么工作 | **Transformers** |
| 想给很多用户提供接口 | **vLLM** |
| 没 GPU 也想跑 | **Ollama（CPU自动优化）** |
| 电脑显存很小 | **Ollama + 小模型（1.5B/3B）** |
| 想给知识库做检索 | **bge-small-zh + Chroma** |
| 想部署到公司服务器 | **Docker + vLLM** |
| 想控制输出 JSON 格式 | **Ollama/Qwen 的 tools** |
| 想把模型封装成自己的 API | **FastAPI** |
| 想全部离线运行 | **本地下载 + Ollama/vLLM** |

## 7. 组合方案示例

### 方案A：个人全本地（零成本）
```
Ollama(qwen2.5:7b) + bge-small-zh + Chroma
= 本地聊天 + 本地知识库 + 本地 Agent
```

### 方案B：团队生产（标准）
```
vLLM(服务模型) + FastAPI(代理/RAG/认证) + Docker(部署) + Nginx(负载均衡)
= 高并发 + 可扩展 + 可运维
```

### 方案C：混合（云端+本地）
```
云端 DeepSeek/GPT（复杂任务）+ 本地 Ollama（简单任务/隐私任务）
= 质量与成本的平衡
```

```
要快用 Ollama，要懂用 Transformers，
要高并发用 vLLM，要省显存用量化，
要检索用 bge，要上线用 Docker。
```
