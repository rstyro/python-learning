## 1. 环境与安装问题

### 1.1 `torch.cuda.is_available()` 返回 False
```
现象：装了 torch，但检测不到 GPU
原因：装的是 CPU 版 PyTorch
解决：
# 卸载
pip uninstall torch

# 重装 CUDA 版（cu118/cu121 取决于驱动）
pip install torch --index-url https://download.pytorch.org/whl/cu118

# 验证
python -c "import torch; print(torch.cuda.is_available())"   # 应为 True
```

### 1.2 安装 CUDA 版 torch 后仍报错 `CUDA driver too old`
```
原因：GPU 驱动太老，不满足 PyTorch 的最低驱动要求
解决：更新显卡驱动（NVIDIA 官网）或用匹配旧驱动的 cu116 等旧版本
```

### 1.3 `ModuleNotFoundError: No module named 'transformers'`
```bash
pip install transformers
```

### 1.4 pip 安装超慢 / 超时
```bash
# 换国内源
pip install transformers -i https://pypi.tuna.tsinghua.edu.cn/simple

# 永久设置（Windows）
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

### 1.5 Windows 下 bitsandbytes 报错
```
现象：pip install bitsandbytes 后 import 或 4bit 加载报错
原因：bitsandbytes 对 Windows 支持有限
解决（三个方案）：
1. 用 GGUF + llama.cpp / Ollama 做量化（推荐）
2. 使用 Windows 版 wheel（社区编译）
3. WSL2 里跑 Linux 版
```

## 2. 显存与内存问题

### 2.1 `CUDA out of memory`
```
最经典报错：
RuntimeError: CUDA out of memory. Tried to allocate 2.00 GiB (GPU 0; 6.00 GiB total capacity)

解决步骤（按顺序试）：
1. 查看占用：nvidia-smi
2. 释放残留进程：nvidia-smi 找到 python 进程 kill 掉
3. 减小 max_new_tokens（生成阶段也吃显存）
4. 减小上下文长度 num_ctx / max_model_len
5. 换更小模型（7B→3B→1.5B）
6. 开启量化（4bit 省 75%）
7. 强制 CPU 推理：device_map="cpu" / --num-gpu 0
```

### 2.2 显存够但很慢 / 部分显存占用
```
原因：模型部分层被放到 CPU（显存不足时的自动行为）
解决：
- 看日志是否有 "offload" 字样
- 显存够的话用 device_map={"": 0} 强制全 GPU
- 检查是否被其他程序占显存
```

### 2.3 内存不足（RAM）
```
现象：加载/推理时电脑卡死或报 MemoryError
解决：
1. 换更小模型
2. 量化（4bit 模型内存需求也降 75%）
3. 关闭其他程序
4. 加虚拟内存（Windows 系统设置）
```

## 3. 下载与网络问题

### 3.1 模型下载慢 / 卡住
```bash
# 设置 HF 镜像（Windows）
$env:HF_ENDPOINT = "https://hf-mirror.com"

# Linux/macOS
export HF_ENDPOINT=https://hf-mirror.com

# 用 ModelScope（国内）
pip install modelscope
python -c "from modelscope import snapshot_download; snapshot_download('Qwen/Qwen2.5-7B-Instruct', local_dir='./models')"
```

### 3.2 `Connection error: SSL: CERTIFICATE_VERIFY_FAILED`
```
原因：证书校验失败（常见于公司网络/代理）
解决：设置环境变量
$env:CURL_CA_BUNDLE = ""
$env:REQUESTS_CA_BUNDLE = ""
```

### 3.3 下载中断后重下
```
HF 下载支持断点续传，重跑相同命令即可。
如果反复失败，用 huggingface_hub 的 resume 参数：
from huggingface_hub import snapshot_download
snapshot_download(repo_id="...", resume_download=True)
```

### 3.4 Ollama pull 极慢
```
解决：
1. 设置 OLLAMA_HOST 无影响，关键是网络本身
2. 从 ModelScope 下载 GGUF → Modelfile 导入 Ollama
3. 或换 Ollama 国内镜像（社区镜像服务）
```

## 4. 模型加载问题

### 4.1 `not a valid package name` / `repo_id must be in the form`
```
原因：模型名格式错误
正确格式：组织名/模型名
✅ "Qwen/Qwen2.5-7B-Instruct"
❌ "Qwen2.5-7B-Instruct"（少了组织名）
❌ "https://huggingface.co/Qwen/Qwen2.5-7B-Instruct"（不要完整URL）
```

### 4.2 `trust_remote_code=True is required`
```
原因：模型仓库包含自定义 Python 代码（如 Qwen-VL 等）
解决：确认模型来源可信后，加载时加参数
model = AutoModelForCausalLM.from_pretrained(..., trust_remote_code=True)
```

### 4.3 `The tokenizer class you load from this checkpoint is not the same`
```
现象：加载时 tokenizer 类型与模型配置不匹配
解决：删除本地缓存重新下载，或显式指定 tokenizer 类型
```

### 4.4 `KeyError: 'chat_template'`
```
现象：模型没有 chat_template（老模型或非 Instruct 版）
解决：
1. 换 Instruct/Chat 版模型
2. 手动拼 prompt（不依赖模板）
```

### 4.5 `sentencepiece is required for ...`
```bash
pip install sentencepiece protobuf
```

## 5. 推理运行问题

### 5.1 `The size of tensor a (X) must match...`
```
原因：输入长度超过模型上下文限制
解决：截断输入 / 增大 max_model_len / 减少历史消息
```

### 5.2 `token indices sequence length is longer than the specified maximum`
```
原因：输入 token 数超限
解决：
1. 缩短输入
2. 用 model.config.max_position_embeddings 查看上限
3. 分段处理长文本
```

### 5.3 推理时程序卡死 / 无响应
```
原因：模型在计算（大模型生成慢是正常的）
解决：
1. 先加流式输出观察是否在推进
2. 小模型/量化模型加速
3. 确认 CPU 使用率/GPU 利用率是否在跳动
```

### 5.4 输出乱码
```
原因：编码问题
解决：确保终端支持 UTF-8，或设置
$env:PYTHONIOENCODING = "utf-8"
```

### 5.5 输出重复（无限重复同一句话）
```
原因：解码参数问题
解决：加 repetition_penalty=1.1，或降低 temperature
```

### 5.6 回答质量差 / 胡说八道
```
排查顺序：
1. 模型太小（1B 以下能力有限）→ 换大模型
2. 量化太重（Q2）→ 用 Q4/Q5
3. 温度太高 → 降到 0.3-0.7
4. 没有 system prompt → 加上角色设定
5. 上下文被截断 → 缩短历史
6. 模型版本（非 Instruct 版不会对话）→ 换 Instruct 版
```

## 6. Ollama 专属问题

### 6.1 `could not connect to default ollama client`
```
原因：Ollama 服务没启动
解决：
1. Windows：托盘图标 → 退出后重新打开
2. 手动启动：ollama serve
3. 检查端口：Test-NetConnection localhost -Port 11434
```

### 6.2 `Error: model "xxx" not found`
```
原因：模型没下载
解决：ollama pull xxx
```

### 6.3 修改环境变量不生效
```
原因：Ollama 已运行，环境变量只在启动时读取
解决：修改后完全退出 Ollama（托盘右键退出）再重启
```

### 6.4 Ollama 加载慢 / 首次响应慢
```
原因：模型首次加载进显存需要时间（几十秒）
解决：
1. 用 --keep-alive 保持模型常驻
2. 提前 warm up（发一个空请求）
3. 换更小模型
```

### 6.5 Ollama 用了 CPU 但想用 GPU
```
检查：
1. ollama --version 是否带 cuda 字样
2. nvidia-smi 确认驱动正常
3. 模型显存是否放得下（放不下自动用 CPU）
4. 日志：~/.ollama/logs 或 ollama serve 前台看
```

## 7. 性能优化清单

### 7.1 推理速度优化（按效果排序）
```
1. GPU 加速（最重要）：确认 torch.cuda.is_available() = True
2. 半精度：torch_dtype=torch.bfloat16 / float16（省一半显存）
3. FlashAttention：attn_implementation="flash_attention_2"
4. vLLM：吞吐提升 10-20 倍（生产首选）
5. torch.compile：1.2-1.5x
6. 减少 max_new_tokens：生成长度与时间成正比
7. 批处理：一次处理多个请求
```

### 7.2 显存优化（按效果排序）
```
1. 4bit 量化：省 75%
2. 换小模型：7B→3B 省一半以上
3. 减小上下文长度：context 也吃显存
4. 半精度：省 50%
5. FlashAttention：省 KV cache 显存
6. 减小 max_new_tokens
```

### 7.3 响应延迟优化（服务场景）
```
1. 模型常驻内存（启动时加载，不要每次请求加载）
2. 预热（启动后发个空请求触发加载）
3. 前缀缓存（vLLM 的 prefix caching）
4. 输出流式化（首 token 延迟大幅降低）
```

## 8. 部署检查清单

### 上线前自检（逐项打勾）
```
□ GPU 可用：torch.cuda.is_available() == True（如果计划用 GPU）
□ 模型可以正常推理：跑通一个最小测试
□ 显存足够：nvidia-smi 确认空闲显存 > 模型需求
□ 流式输出正常：前端能收到 SSE 流
□ 并发正常：并发 10 个请求不崩
□ 认证生效：无 Key 访问被拒绝
□ 限流生效：超频访问被限制
□ 错误处理：模型报错返回友好信息而非 500 裸奔
□ 日志完整：请求/响应/耗时/错误都有记录
□ 环境变量正确：密钥不在代码里
□ Docker 构建成功：docker build 通过
□ 模型已本地化：不依赖运行时联网下载
□ 文档更新：API 文档、部署文档、环境变量说明
```

## 9. 模型缓存路径速查

不同的引擎/工具把模型存在不同位置，磁盘空间不足时需手动清理：

| 引擎/工具 | 默认缓存路径（Windows） | 环境变量 |
|----------|----------------------|---------|
| HuggingFace | `C:\Users\<用户名>\.cache\huggingface\hub\` | `HF_HOME` |
| Ollama | `%LOCALAPPDATA%\ollama\models\` | `OLLAMA_MODELS` |
| vLLM | 同 HuggingFace 缓存 | 同 `HF_HOME` |
| llama.cpp | 用户手动指定（无默认缓存） | 无，`-m` 参数指定 |
| ModelScope | `C:\Users\<用户名>\.cache\modelscope\hub\` | `MODELSCOPE_CACHE` |
| pip 缓存 | `C:\Users\<用户名>\.cache\pip\` | `PIP_CACHE_DIR` |
| transformers 模型 | 同 HuggingFace 缓存 | 同 `HF_HOME` |

### 手动迁移/清理缓存

```bash
# HuggingFace 迁移到 D 盘（Windows PowerShell）
$env:HF_HOME = "D:\huggingface\cache"

# Ollama 迁移到 D 盘
$env:OLLAMA_MODELS = "D:\ollama\models"

# 清理 HuggingFace 缓存（用 huggingface_hub CLI）
pip install huggingface_hub
huggingface-cli delete-cache
# > 交互式选择删除哪些模型的缓存

# 或手动删除文件夹
Remove-Item -Recurse -Force "$env:USERPROFILE\.cache\huggingface\hub"
```

> ⚠️ 删除前确认：重新下载 7B 模型可能需要 10-15GB 流量和数十分钟。

### 磁盘空间不足排查
```bash
# 查看各缓存目录占用（Windows PowerShell）
function Get-FolderSize { param($path); (Get-ChildItem -LiteralPath $path -Recurse | Measure-Object Length -Sum).Sum / 1GB }
Write-Output ("HF缓存: {0:N1}GB" -f (Get-FolderSize "$env:USERPROFILE\.cache\huggingface"))
Write-Output ("Ollama:  {0:N1}GB" -f (Get-FolderSize "$env:LOCALAPPDATA\ollama\models"))
Write-Output ("pip缓存: {0:N1}GB" -f (Get-FolderSize "$env:USERPROFILE\.cache\pip"))
```

## 10. Docker 部署问题

### 10.1 容器内 GPU 不可用
```
现象：docker run --gpus all 报错或容器内 nvidia-smi 报错
原因：未安装 nvidia-container-toolkit
解决：
  # Windows：Docker Desktop Settings → Resources → 启用 GPU support
  # Linux：
  distribution=$(. /etc/os-release;echo $ID$VERSION_ID)
  curl -s -L https://nvidia.github.io/nvidia-docker/gpgkey | sudo apt-key add -
  curl -s -L https://nvidia.github.io/nvidia-docker/$distribution/nvidia-docker.list | \
      sudo tee /etc/apt/sources.list.d/nvidia-docker.list
  sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
  sudo systemctl restart docker
  # 测试：
  docker run --rm --gpus all nvidia/cuda:12.1-base nvidia-smi
```

### 10.2 镜像体积过大
```
现象：docker build 后镜像 10GB+
原因：模型权重打包进了镜像
解决：
  1. 用卷挂载模型（docker-compose.yml 的 volumes 字段）
  2. 或用 .dockerignore 排除模型目录：
     echo "models/" >> .dockerignore
  3. 或分阶段构建，只保留必要文件

推荐方案（模型文件挂载，不进镜像）：
docker run -v ./models:/app/models --gpus all llm-service
```

### 10.3 容器内 OOM 但宿主机显存够
```
现象：容器内模型推理 OOM，但 nvidia-smi（宿主机）显示有空闲显存
原因：Docker 可能限制了容器可用显存（默认无限制，但某些配置有）
解决：
  1. 检查是否设置了 --shm-size（共享内存不足可能导致 OOM）
     docker run --shm-size=8g ...
  2. 检查 nvidia-container-runtime 配置
  3. 增加 docker run --memory 和 --memory-swap 限制
```

### 10.4 Windows Docker Desktop + GPU
```
Windows 下 Docker Desktop 使用 WSL2 后端时：
- 需要在 Docker Desktop Settings → Resources → WSL Integration 启用
- 需要在 Docker Desktop Settings → Resources → Advanced 启用 GPU support
- 确保 WSL2 里安装了正确的 NVIDIA 驱动（Windows 驱动会自动透传）
- 测试：docker run --rm --gpus all nvidia/cuda:12.1-base nvidia-smi
```

### 10.5 Docker Compose GPU 配置
```yaml
# docker-compose.yml GPU 配置（新版语法）
services:
  llm:
    image: llm-service
    ports:
      - "8000:8000"
    volumes:
      - ./models:/app/models
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1            # 或 all
              capabilities: [gpu]
    # 共享内存（大模型推理需要）
    shm_size: '8gb'
```

## 11. vLLM 专属排错

### 11.1 `ImportError: libcuda.so.1: cannot open shared object file`
```
原因：vLLM 找不到 CUDA 运行时
解决：
  1. 确认驱动正确安装：nvidia-smi
  2. 确认 LD_LIBRARY_PATH 包含 CUDA 库路径
  3. Docker 中运行：保证 --gpus all
```

### 11.2 `vLLM only supports NVIDIA GPUs and AMD ROCm`
```
原因：vLLM 不支持纯 CPU，也不支持 Intel GPU 或 Apple Silicon
解决：
  Windows: WSL2 + Docker
  无 GPU: 换 Ollama / llama-cpp-python
  Apple Silicon: 换 MLX 或 llama.cpp（Metal 后端）
```

### 11.3 `ValueError: The model's max seq len (...) is larger than the maximum number of tokens`
```
原因：vLLM 默认 max_model_len 小于模型配置
解决：
  vllm serve Qwen/Qwen2.5-7B-Instruct --max-model-len 32768
  # 增大到模型支持的上限（但会占用更多显存）
```

### 11.4 vLLM serve 启动后长时间无响应
```
原因：模型首次加载需编译 CUDA kernel（JIT 编译，首次约 2-5 分钟）
解决：耐心等待，编译完成后会输出 "Uvicorn running on..."
      后续启动会使用编译缓存，速度大幅加快。
```

### 11.5 `AttributeError: 'NoneType' object has no attribute 'request_id'`
```
原因：vLLM 版本与 transformers 版本不兼容（常见于升级后）
解决：
  pip install vllm --upgrade
  pip install transformers --upgrade
  # 确保两者版本兼容
```

## 速查：报错 → 第一反应

| 报错 | 第一反应 |
|------|---------|
| out of memory | 看显存 → 量化/换小模型/关程序 |
| connection error | 看网络 → 设镜像/检查服务是否启动 |
| not found | 看名字 → 检查模型名/文件路径 |
| version mismatch | 看版本 → pip 升级/降级对应库 |
| permission denied | 看权限 → 加 sudo/管理员/检查端口占用 |
| 乱码 | 看编码 → UTF-8 环境变量 |
| 卡死 | 看资源 → 确认在计算，加流式观察 |
